# Specificity-Determining Position (SDP) Score Analysis

`SDP` folder contains the scripts, multiple sequence alignment and ancestral seqeunce resconstruction files, and final scores for the analysis of SDPs in Class C GPCR subfamilies. The goal of this analysis is to identify key residues that confer functional specificity to each subfamily.

The methodology is based on a phylogeny-aware scoring approach, where SDP scores are calculated separately for each protein domain (e.g., ANF, CR, TM).


The workflow for calculating SDP scores for each domain within a subfamily is as follows:

1.  **Sequence Extraction**: For a given subfamily, each domain sequences were extracted based on `hmmscan` results. For comparison, the same domains were collected from all other subfamilies. Loop regions were included in the sequences.
2.  **Multiple Sequence Alignment**: The collected domain sequences were aligned using **MAFFT (v7.490)** with the `auto` model.
3.  **Alignment Curation**: Positions in the alignment that corresponded to gaps in the human receptor sequence of the analyzed subfamily were removed.
4.  **Ancestral Sequence Reconstruction**: Phylogenetic trees for each domain alignment were constructed using the maximum likelihood method in **IQ-TREE (v2.0.6)** with the JTT+R10 model.
5.  **SDP Score Calculation**: A phylogeny-based scoring algorithm, **adjPHACT** (an adaptation of the PHACT algorithm), was used in combination with methods extended from Bradley & Beltrao (2019) to calculate the final SDP scores.
6.  **Visualization**: The calculated SDPs were mapped onto representative protein structures using **UCSF Chimera**.


This repository is organized into three main folders:

### 1. `SDP_codes/`

This folder contains the source code and scripts used to perform the SDP score calculations. 

To calculate the SDP score for a domain of a subfamily, you primarily need to run `Test_SDP.R`.

This main script calculates the SDP scores by calling functions from the other scripts:

It first uses functions from `PHACT_ComputeScore_Upd.R` to compute initial, phylogeny-based scores for each subfamily from the provided alignments and tree files.
Next, it calls `Specifictiy_Code_2.R` to take those initial scores, weigh them by phylogenetic distance between subfamilies, and calculate the final, weighted SDP score.
Finally, `ComputeThresholds.R` can be used as a separate script to analyze the final SDP score files and determine a significance threshold for identifying the most important positions.


### 2. `Domain_based_SDP_analysis_files/`

This folder contains the necessary input files. For each receptor and each of its domains, there are:
* **Multiple Sequence Alignments**: Output files from MAFFT used for tree building and scoring.
* **Ancestral Sequence Trees**: Phylogenetic tree files (`_ancestral.treefile`) generated by IQ-TREE.

### 3. `SDP_score_files/`

This folder contains the final output of the analysis. It includes the calculated SDP score files for each domain of every receptor analyzed in this study.



* **Alignment**: [MAFFT (v7.490)](https://mafft.cbrc.jp/alignment/software/)
* **Phylogenetic Inference**: [IQ-TREE (v2.0.6)](http://www.iqtree.org/)
* **SDP Calculation**: `PHACT_ComputeScore_Upd.R`, `Specifictiy_Code_2.R`, `Test_SDP.R`, `ComputeThresholds.R`


# Sequence Conservation Analysis

This folder contains the scripts and results for calculating sequence identity scores and visualizing conservation across the Transmembrane (TM) domains of 22 Class C GPCR subfamilies.


1.  **Identity Score Calculation**:
    The Python script **`calculate_identity.py`** is used to compute sequence identity scores. The script can be used to calculate scores for the entire set or for specific subsets of sequences, such as analyzing only those proteins that contain both VFT and CR domains.

2.  **Conservation Visualization**:
    The R script **`identity_logos.R`** is used to generate sequence logos from an alignment. This script is used to visualize conserved residues that are conserved in more than 80% of the sequences in the provided alignment as logos.

### Folder Contents

* **`calculate_identity.py`**: A Python script to calculate sequence identity scores from a multiple sequence alignment.
* **`identity_logos.R`**: An R script to generate sequence logos for highly conserved positions.
* **Alignment Files**: The master alignment of TM domains and any specific subsets used for analysis.
* **Output Files**: The calculated identity score tables and the generated sequence logo images.

# Phylogenetic Analysis of Class C GPCRs

This directory contains the data and results for identifying orthologs for each subfamily of Class C GPCRs by using 478 eukaryotic proteomes.


We identified Class C GPCRs from proteomes using **HMMER** and found initial orthologs with reciprocal **BLAST** searches. We refined the ortholog sets for each subfamily using custom-built profile HMMs. The final ortholog sets were aligned with **MAFFT (E-INS-I)** and trimmed with **trimAl**. We constructed Maximum Likelihood phylogenetic trees from the alignments using **RAxML**. For each receptor subfamily, we built a phylogenetic tree by using its sequences and the sequences from its closely related subfamilies.

For example, to refine the orthologs for the mGluR4/6/7/8, we built a single tree containing all identified hits for these four receptors, and the sequences for the other human mGluRs (1, 2, 3, and 5).

* `subfamily_sequences/`: Contains FASTA files of protein sequences for each subfamily.
* `einsi/`: Contains the final, trimmed multiple sequence alignments.
* `raxml-ng/`: Contains the final phylogenetic trees and associated files from RAxML.
* `likes_removed_trees`: containes file final tree files for each subfamily that contains functionally equivalent orthologs for each subfamily
* `class_c_rep_tree`: containes the representative sequences selected from different species for each subfamily to build a representative class C GPCR tree. Then, we took each subfamily tree and merged it to the corresponding clade of this representative tree by using ETE3. The phyloegentic tree was built by using the following command:

`raxml-ng --all --msa einsi_class_c_rep_with264_casr_likes.fasta --model JTT --data-type AA --prefix rep_tree_with_264_casr_likes --seed 2 --threads 8 --bs-metric fbp,tbe`



# Molecular Docking of GABA

### Structure Preparation and Docking Protocol

The structures used for this analysis were the full Cryo-EM structure of the Baclofen-bound GABA(B) complex (PDB ID: **7C7Q**) and the crystal structure of the extracellular domain of GABA(B) bound with GABA (PDB ID: **4MS3**).

Structure preparation was conducted using **AutoDock Tools (ver 1.5.7)**. Both the receptor and ligand PDB files were processed to generate the **PDBQT** file format required for docking.

The docking simulation itself was performed using **AutoDock Vina** on a local HP ThinkPad machine. After loading the prepared receptor and ligand PDBQT files, the binding site was defined by placing a grid box over the known ligand binding area.

A configuration file, `GABA.conf`, was created for the docking run. All files related to this analysis are located in the `GABBA_Docking` folder.
